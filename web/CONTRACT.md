# XCPC Cloud contract

Next.js App Router full-stack app. Node 24, node:sqlite (WAL + foreign keys). Durable file at VP_DATA_DIR outside releases. UI imitates NovaJudge: light academic/contest tables, restrained blue navigation, green/red/blue problem cells. No judge cookies/API secrets/source code are included in client state synchronization. Only virtual print jobs contain code.

## JSON API

All success bodies are `{data: ...}`; failures `{error: string}`, meaningful HTTP status. User fields: `id,useraccount,username,realname,numberid,email,role`; own authenticated profiles also expose `externalId` (association login `data.userId`, string or null). IDs strings. Auth: HttpOnly SameSite=Lax secure production cookie plus Bearer token for CLI; login response data `{user,token,expiresAt}`. UTC ISO timestamps.

- POST /api/auth/login `{account,password}` external association login; POST /api/auth/admin-login `{account,password}` local bootstrap admin; GET /api/auth/me returns user; POST /api/auth/logout.
- GET/PUT /api/admin/settings admin only `{externalBaseUrl,externalAppKey}` (GET masked key + configured flag); env initial VP_EXTERNAL_APP_KEY, VP_EXTERNAL_BASE_URL. Bootstrap account env VP_ADMIN_ACCOUNT default admin and VP_ADMIN_PASSWORD required at first boot. No secrets in source.
- GET/POST /api/admin/api-keys and DELETE /api/admin/api-keys/:id: admin session only; create named random read-only history keys, return plaintext once, store SHA-256 only, list prefix and timestamps, revoke immediately. Maximum 100 active keys; create/revoke audited.
- GET /api/external/vp-history?externalId=&contestUrl=&limit=20&offset=0: API Key Bearer or X-API-Key only, never a user session. Requires exact association ID and canonical original contest URL; no email lookup. Returns `{user,contestUrl,total,limit,offset,records,serverNow}` with ended VP details, including immutable team-roster membership. Excludes ongoing/scheduled/failed/cancelled, live and BT records. Limit 1–100; per-key 120 requests/minute per process, 429 + Retry-After:60. See [calling guide](../docs/vp-history-api.md).
- GET /api/users?search=... authenticated search by real name/student number/account; minimum 2 characters; only public member profile fields.
- GET/POST /api/teams `{nameZh,nameEn}`. GET/PATCH/DELETE /api/teams/:id. Team `{id,nameZh,nameEn,captainId,members:User[],createdAt}`; creator captain included, 1–3 members; captain edits/removes members via PATCH `{nameZh?,nameEn?,removeUserId?}`. Deletion retains historical data.
- POST /api/teams/:id/invitations `{userId}` captain only; membership change on accept is transactional and capacity checked.
- GET /api/notifications includes `{id,kind,title,message,status,createdAt,teamId?,roomId?,canRespond}`; POST /api/notifications/:id/respond `{accept:boolean}`. Rejects can be re-invited. Notifications remain for audit; only target recipient responds. Team room invitations target team captain.
- GET/POST /api/rooms `{name,contestUrl,startsAt,freezeMinutes,scoringSystem,externalRankUrl?}`. Only cf/gym/qoj contest URLs accepted. Creator is NOT automatically participating. List visible to creator or accepted participants; invitations appear in notifications. `freezeMinutes` is required: integer 0–10080, minutes before the end; 0 disables freezing. `scoringSystem` is required: `ICPC` or `CCPC` for CF/Gym; QOJ and contest.ucup.ac also permit `OI`/`IOI` (UI defaults ICPC). Existing rooms safely migrate to 0 / ICPC / null external scoreboard. `externalRankUrl` is optional/null and accepts only HTTPS page URLs at `board.xcpcio.com/icpc/...`, `board.xcpcio.com/ccpc/...`, or `rank.iccpc.cn/r/{uuid}`; it is rejected for OI/IOI. An empty string clears it; omitted PATCH fields retain the saved value. Clients import the configured scoreboard when joining/resuming the room. Room `{id,name,contestUrl,startsAt,scoringSystem,externalRankUrl,freezeMinutes,endsAt,durationSeconds,durationSource,freezeAt,freezeDurationSeconds,frozen,createdBy,createdAt,participants:[{id,type,userId?,teamId?,label,captainId,members:User[]}],canManage,participation?,serverNow}`. Platform duration is learned from the first valid client rules snapshot and then checked for consistency; until then the default is five hours (`durationSource:'default'`, otherwise `'platform'`).
- GET/PATCH /api/rooms/:id; POST /api/rooms/:id/invitations `{userId}` OR `{teamId}`. PATCH only before start. Once any client has reserved the room, contest URL, start, freeze, scoring system and external scoreboard URL are locked (the name remains editable). Creator manages, invites self explicitly. Each user can only occupy one accepted participation per room. Team member snapshot and captain frozen on invitation acceptance; overlapping accepted participation rejected.
- GET /api/rooms/:id/virtual-board serves the room's /rank page. The response includes public original rows (including starred entries), same-room VP rows, the viewer's pinned entry, revealed problem columns, and the effective source. Starred entries do not consume a rank. An explicit public external URL takes precedence. The Qinhuangdao Gym mirror has a verified default archive. Other rooms use the verified public `roomBoard` snapshot sent by a registered terminal client when available. The server's room schedule controls scoring time and freeze. Practice, standalone VP and other room histories are excluded.
  Before freeze, CCPC returns `rowProblemOrder: true` and a `problemSlots` array per row. Revealed problems use shared labeled columns at the left. Anonymous accepted problems follow in solve order and may carry a first-solve flag. Other attempted or pending problems follow before the blank anonymous slots. During freeze or after the contest, the board returns to the shared problem order. When the original archive provides medal quotas, the board reports provisional medal bands until the contest ends. VP medals compare against original official teams.
- GET /api/rooms/:id/leaderboard => `{room,rows:[{participantId,label,rank,solved,penalty,cells,historyId?,lastSyncedAt?,frozen,canViewHistory}],problems:string[],serverNow,publicProblemStatistics,statisticsAt,...freezeMetadata}`. Rank is ORIGINAL platform rank, never local-relative rank; Sort ICPC rows by visible solved/penalty; graded rows by their visible native points, without changing the native rank. Poll 5 seconds while visible. With a nonzero freeze setting, the freeze interval is `[max(startsAt,endsAt-freezeMinutes×60s),endsAt)`; with 0, `freezeAt:null` and `frozen:false` throughout. Timing uses server time; automatic release at the scheduled end, never from a client's early completion. Like NovaJudge, the public leaderboard freezes **all rows, including the viewer's own team**. Totals are rebuilt from prefreeze submission timestamps, while later attempts become pending. A prefreeze submission judged during the freeze still updates its public result. Native rank is the last value received by the server before freeze; if unavailable it is `?`. That rank and receipt time survive restarts. Own/team actual results remain live in mysubmit and own history only. Future submissions do not count early. `canViewHistory` is true only for self/team until scheduled end, then also for other accepted room viewers/creator; the UI must not link foreign history before that time.
- GET /api/rooms/:id/mysubmit => `{room,participation,history:History|null,submissions:Submission[],serverNow}`. Only an accepted participant may access it; snapshot team members share the full current team submissions, including during freeze. A nonparticipating room creator has no access. Before first client sync, history is null and submissions empty.
- GET /api/rooms/:id/prints => own accepted participant's jobs ONLY, even room creator cannot inspect others. GET /api/prints/:id same restriction. Print `{id,roomId,participantLabel,filename,language,createdAt,code?}`; list omits code.
- GET /api/history?search=&type=vp|live|bt => array `{id,contestName,contestUrl,mode,rank,solved,penalty,problems:string[],cells,startedAt,endedAt,participantLabel,participantType,updatedAt,rules,frozen}` own/accepted team records. GET /api/history/:id also `{submissions:[{id,problem,submittedAt,verdict,practice,url?}],...}`. BT has null startedAt/endedAt. Owner and same participant snapshot members always retain full detail. Foreign room history returns **404 until the scheduled room end, including before start and throughout the entire VP**, independently of freeze and independently of a client's early completion. Room creator has no bypass. After scheduled end, room creator/other accepted room participants may view historical detail (records only, never prints). Room records include freeze metadata and `freezeActive` for the room. This follows NovaJudge's ordinary-user rule that foreign submissions are only viewable after a contest; this application intentionally grants no jury privilege to room creators.

## Terminal API

- POST /api/client/rooms/:id/authorize `{}` => `{room:{id,name,contestUrl,startsAt,freezeMinutes,scoringSystem,externalRankUrl?},participant:{id,type,label,captainId,members},canSubmit,serverNow}`. Require accepted participant. Team only captain may start/submit/sync; other members web readonly.
- POST /api/client/sync `{localId,roomId?,contest:{platform,contestId,url,name,problems:string[],rules?:{duration:number,penalty_minutes:number,penalty_rounding?:'per_problem'|'total_seconds',compile_penalty?:boolean,freeze_minutes?:number,scoring?:'ICPC'|'CF'|'OI'|'IOI'|'WEEKLY',score_policy?:'best'|'latest'|'subtasks'|'native',problem_max_scores?:Record<string,number>,contest_format?:'ICPC'|'CCPC'|'OI'|'IOI',problem_reveal_count?:50|null}},mode:'vp'|'live'|'bt',startedAt?:ISO,endedAt?:ISO,rank:string,solved:number,penalty:number,points?:number,cells:{[label]:{tries:number,pending:number,solved:boolean,practiceSolved:boolean,solveTime?:number,points?:number,maxPoints?:number}},submissions:[{id,problem,submittedAt:ISO,verdict,practice:boolean,url?,points?:number}],publicStatistics?:{submitted:Record<string,number>,attempted:Record<string,number>,accepted:Record<string,number>},revealedProblems?:string[],statisticsAt?:ISO,revision:number}` => `{id}`. Duration uses positive integer seconds, max seven days; legacy clients without compile_penalty default false. Rules are persisted so public freeze scoring follows native penalty settings. Snapshot freeze_minutes may be fractional to preserve a native cutoff measured to the second; online room freezeMinutes remains an integer. Idempotent by user/localId or room/participant; server verifies room contest URL and accepted captain. Limit request 2 MiB, max 20k records; reject foreign/replayed stale snapshots, preserve final verdicts. Never accept cookies/API keys/passwords; whitelist persisted fields. Original local source submission stays in current platform workflow.
- POST /api/client/prints `{roomId,filename,code,language?}` => `{id,url}`; authorized participant only; code <=512KiB UTF8; basename filename, HTTPS plain text code page, no execution.
- GET /api/health => `{status:'ok'}`.

Frontend owns app/layout.tsx, app/globals.css, app/[[...path]]/page.tsx and components. Backend owns lib + app/api/[...path]/route.ts + API tests. Root owns package/config/build/deployment. Terminal agent owns Python and browser extension integration + terminal tests. Website base https://vp.cwnupaa.com. CLI commands `xcpc login`, `xcpc logout`, `xcpc account`, `printfile a.cpp`; `vp https://vp.cwnupaa.com/vp/ID` must route to cloud authorization and current native VP scheduling. Store cloud credentials separately, private mode 0600; website never persists association password. Sync standalone VP/live/BT too, including web-origin submissions already captured by current monitor.


Room settings override snapshot `freeze_minutes`, `contest_format` and `problem_reveal_count` on the server and must override native defaults and local prompts on the client. CCPC retains ICPC scoring and uses a 50-original-team reveal threshold; starred original teams count toward revealing a label, room participants never do. A client sends timestamped original timeline statistics and its verified revealed labels. The leaderboard returns `publicProblemStatistics:[{label:string|null,submitted:number|null,attempted:number|null,accepted:number|null}]` and `statisticsAt`; unrevealed labels are actually removed from this response and their columns sorted by accepted, attempted, then submitted descending. All labels are revealed during freeze and after the scheduled end. While frozen, the latest reference no later than the cutoff is retained; late current statistics cannot replace it. Missing original statistics remain unknown.

Native scoring snapshots are persisted without estimating platform formulas. OI uses latest judged event scores; IOI/CF/WEEKLY use best per-problem native scores (`native` is normalized to `best`). `subtasks` IOI cannot be rebuilt from whole-submission totals: its frozen native score/cells use the latest prefreeze snapshot, or remain unknown if unavailable. Native signed total points (including CF adjustments) are accepted; per-problem points and maxima must be finite nonnegative numbers. For CF/best/latest freeze projection, the last prefreeze native total plus changes in visible event points preserves native adjustments; post-cutoff points and URLs are omitted. A prefreeze pending result may still resolve publicly. Standalone BT always has null points, no rank or penalty, and only practice attempts / accepted colors. Continuing an ended VP/live in BT preserves its original contest score and rank, with practice colors added to the same record.

External scoreboard selection is stored with room rules and returned as `externalRankUrl` (string or null) in room/list/authorize responses and at the top level of client restore snapshots. The server stores only the validated public page URL; the local client downloads and validates the public archive without judge credentials.

Standalone VP sync also accepts `externalRankUrl`: a canonical supported public page URL, or null to clear the selection. Omission preserves an existing selection for older clients. History list/detail and restore responses expose the selection. An explicitly configured room board must match; invalid URLs never enter history. Active VP/live ranks follow successive snapshots until an actually ended, finalized result is preserved for practice continuation; a future `endedAt` alone does not finalize the rank.

Completed external-board snapshots may include `prize` (`Gold`, `Silver`, `Bronze`, `None`, `Unknown`, or null) and `prizeSource` (`original` or `unavailable`). Verified prizes require an ended VP, its selected external board and matching verified original rank. History/restore responses expose prizes only after finalization; older clients and practice continuation preserve a confirmed final prize, while changing the selected board clears it. No verified medal rules produces `Unknown`, not `None`.

`penalty_rounding` defaults to `per_problem`. For `total_seconds`, ICPC public/frozen projections floor each accepted elapsed time to seconds, sum these plus wrong-attempt penalty seconds across solved problems, and then floor the total to minutes; displayed cell solve times stay in minutes. Restore preserves this rule.

New clients include `roomExternalRankUrl` (string or null) in room sync requests. When present, its canonical page URL must match the room's current external scoreboard, otherwise the server returns 409 before writing any history. Omitted fields remain compatible with existing clients.
